Where tasks begin

Skribly Tracker

An issue tracker in the browser, with an API that lets agents read tasks the same way people do.

Overview

Skribly Tracker plans the work that the rest of Skribly carries out. It has projects, issues, boards, comments and time logs, in Polish and English.

Its REST API uses personal tokens with the same roles as people. Skribly Agent and the task skill from agent-skills use it as their default tracker.

Projects and issues
Keys such as AGENT-12, issue types, priorities, labels, assignees, estimates and subtasks.
Board and list
A Kanban board with drag and drop, and a list with filters and search.
Teamwork
Markdown comments, time entries, watchers, attachments and an activity log.
Your own workflow
Statuses for each project that you can rename, reorder and extend.
Roles and tokens
Admin, member and viewer roles, with read-only or read-write API tokens.
Webhooks
Signed events for issues and comments, delivered by a queue worker.
Light and dark themes
Follows the system, and you can switch it in the top bar.
Accessibility panel
Text size, contrast, fonts and motion on every page.

Workflows

Plan, then hand it to an agent

  1. Create an issue with a type, a priority and labels.
  2. Assign it. It appears in Skribly Agent under Assigned to me.
  3. Start it with an agent, or run /task AGENT-12 in your agent.
  4. The agent comments, changes the status and logs time through the API.
  5. You review the issue's history, comments and time.

React to changes

Signed webhooks send issue and comment events to any address you choose.

API

REST API v1 uses personal access tokens with the same roles as people. It was designed for coding agents as much as for people, and it maps one to one onto what Skribly Agent needs from a tracker.

Security

  • API tokens and webhook secrets are shown once and never logged.
  • A viewer's token never changes data, and tokens can be read-only.
  • Webhooks are signed with HMAC-SHA256.
  • Markdown is rendered with raw HTML escaped, and attachments stay on a private disk.
  • More than 240 API requests a minute per user are refused.
