Skills catalogue

All 39 skills in agent-skills. Install them once, then call one by name or describe what you want, and the agent picks the skill.

Filter by name or description

Skills shown:

Workflow

Move a task from a ticket to a commit, and keep the project around it healthy.

  • task

    Task workflow

    Runs a task from a tracker issue or a sentence to an approved local commit.

    Use it when: You start, resume or hand over any piece of work.

    Example: /task 482

  • commit

    Commit in project style

    Proposes a message in the project's convention and commits only after you approve.

    Use it when: A change is ready, or mixed changes need splitting.

    Example: /commit

  • handoff

    Handoff and resume

    Saves or reads a state file, so another agent or a new session can continue.

    Use it when: You near a usage limit, switch agents or end the day.

    Example: /handoff resume 482

  • orchestrate

    Parallel subagents

    Splits big work into independent parts, runs them in parallel, then merges and verifies.

    Use it when: A job spans many independent modules or pages.

    Example: /orchestrate migrate all forms

  • estimate

    Task estimation

    Sizes a task in hours, with risks and open questions, without touching code.

    Use it when: You need to size work before planning it.

    Example: /estimate 482

  • ci-setup

    CI pipeline setup

    Creates or fixes GitHub Actions or GitLab CI, and reviews workflows for security problems.

    Use it when: A project has no CI, or CI is slow or flaky.

    Example: /ci-setup

  • deps-update

    Safe dependency upgrades

    Groups outdated packages by risk and upgrades one group at a time, with tests and a commit each.

    Use it when: Dependencies are behind, or before a framework upgrade.

    Example: /deps-update

  • project

    Project profile

    Detects the stack, commands, commit style and base branch and keeps them in .skribly/project.json, which every other skill reads first.

    Use it when: You start in a repository an agent has not seen.

    Example: /project

  • plan-step

    Plan a work package

    Writes or expands a plan work package in one fixed shape: tasks with files, steps and checks, and a done list.

    Use it when: You turn a plan into steps an agent can run.

    Example: /plan-step

  • run-step

    Run a work package

    Carries out one work package task by task: a short branch, its check, a commit, a merge into develop.

    Use it when: A step of the plan is ready to build.

    Example: /run-step

  • release

    Release checklist

    Walks the release checklist and runs the read-only checks before a release. It never bumps, tags or publishes.

    Use it when: You prepare a release.

    Example: /release

  • standard

    Repository standard

    Checks a repository against the Skribly standard and prints one line per check, then guides the repair.

    Use it when: You want to know if a repository follows the shared rules.

    Example: /standard

  • slice

    Vertical slice

    Scaffolds a command or query slice, or a whole module, by copying the shape of the app's own reference module.

    Use it when: You add a feature to an app made from the Skribly app template.

    Example: /slice

  • seed

    Module seeds

    Writes the deterministic demo and minimal seeds of a module, with fixed ids and a fixed clock.

    Use it when: A new module needs data to develop and demo against.

    Example: /seed

Quality and tests

Find problems before they reach a commit.

  • test-loop

    Focused test loop

    Runs only the checks affected by the change and fixes failures in up to three attempts.

    Use it when: You want green checks for the current change.

    Example: /test-loop

  • backend-tests

    Backend tests

    Writes and runs backend tests with a test database, factories and mocked HTTP.

    Use it when: New backend code needs tests.

    Example: /backend-tests

  • api-tests

    API contract tests

    Contract and integration tests for REST and GraphQL, including sign-in flows and error cases.

    Use it when: An API changes, or the spec and the code may disagree.

    Example: /api-tests

  • e2e-tests

    Playwright end-to-end tests

    Playwright specs for changed user flows, with flaky tests fixed at the cause.

    Use it when: A user-facing flow changes or a test is flaky.

    Example: /e2e-tests

  • load-test

    Load testing

    Runs k6, autocannon or Locust from smoke to stress and reads the results through a summary.

    Use it when: You need capacity numbers or want to confirm a fix under load.

    Example: /load-test GET /api/orders

  • review

    Self-review before commit

    Reviews the diff before committing, with severity, file:line and a fix for each finding.

    Use it when: Before every commit or pull request.

    Example: /review

  • debug

    Root-cause debugging

    Reproduces, narrows down and proves the cause, then applies the smallest fix.

    Use it when: Something is broken or a regression appeared.

    Example: /debug

  • refactor

    Behaviour-preserving refactor

    Writes characterization tests first, then moves in small verified steps.

    Use it when: Code must be split or cleaned up without changing what it does.

    Example: /refactor split OrderService

  • db-migrations

    Safe database migrations

    Reviews and writes zero-downtime migrations for Django, Laravel, Prisma, Alembic, Flyway and Rails.

    Use it when: A migration touches an existing table, especially a big one.

    Example: /db-migrations

  • i18n

    Translations and i18n

    Finds missing, empty and extra keys and placeholder mismatches, and extracts hard-coded strings.

    Use it when: UI text changes or a language is added.

    Example: /i18n

  • browser-check

    Headless browser check

    Takes desktop and mobile screenshots of only the changed element and reports console errors, with your consent.

    Use it when: A visible change should be checked.

    Example: /browser-check

  • design-review

    Design review of a page

    Reviews a page or component against a fixed checklist: a script scans the files, the rest is judged on screenshots.

    Use it when: You change the look of a page.

    Example: /design-review

Performance

Measure first, then prove the gain.

  • pagespeed

    PageSpeed and Web Vitals

    Measures Core Web Vitals with PageSpeed Insights or local Lighthouse, then runs a fix-and-measure loop.

    Use it when: A page is slow, or before a launch.

    Example: /pagespeed http://localhost:3000

  • perf-backend

    Backend performance

    Finds N+1 queries, adds indexes from EXPLAIN and proves the gain with before and after numbers.

    Use it when: An endpoint is slow or runs too many queries.

    Example: /perf-backend

Security and accessibility

Check for what should never ship.

  • security-audit

    Security audit

    Checks for secrets, vulnerable dependencies and dangerous code patterns. It only reads.

    Use it when: Before a release or merge, or after adding sign-in or uploads.

    Example: /security-audit

  • wcag-audit

    WCAG 2.2 AA audit

    Reviews changed UI with axe-core and a targeted checklist, and gives concrete fixes.

    Use it when: UI changes, or before an accessibility review.

    Example: /wcag-audit

  • docker

    Docker and compose review

    Reviews and fixes Dockerfiles and compose files: multi-stage builds, pinned images, non-root users and secrets.

    Use it when: You containerise an app, or before deploying.

    Example: /docker

Docs

Keep what people and agents read up to date.

  • project-docs

    Project knowledge docs

    Builds a .docs/ folder and a short AGENTS.md or CLAUDE.md that points to it.

    Use it when: You bring agents or people into a project.

    Example: /project-docs

  • seo-audit

    Technical SEO audit

    Checks meta tags, headings, canonical links, robots, sitemaps, hreflang, Open Graph and JSON-LD.

    Use it when: You launch or move pages, or pages are not indexed.

    Example: /seo-audit

  • release-notes

    Release notes

    Writes release notes and changelog entries from git history, in the project's style.

    Use it when: You prepare a release.

    Example: /release-notes

  • adr

    Architecture decision record

    Writes a numbered decision record, keeps the index, and replaces an accepted record with a link instead of editing it.

    Use it when: You make a choice that is costly to reverse.

    Example: /adr

  • docs-sync

    Docs move with the code

    Checks that a visible change also updated both language files, the repository docs and the changelog.

    Use it when: Before you commit a change a user can see.

    Example: /docs-sync

  • newsletter

    Newsletter issue

    Drafts one issue in Polish and English from public feeds, with a source under every item, and validates the folder.

    Use it when: You prepare the next issue of the newsletter.

    Example: /newsletter

Meta

Rules for how an agent works.

  • token-saver

    Token saver

    Gives an agent rules for small context: search first, read line ranges and condense logs.

    Use it when: A session grows long or you near a usage limit.

    Example: /token-saver

  • learn

    Project lessons

    Records a confirmed lesson about the project in .skribly/lessons.md, only after you agree, so later skills start smarter.

    Use it when: A command, convention or pitfall is worth remembering.

    Example: /learn
