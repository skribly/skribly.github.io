From a task in the tracker to a commit you reviewed

You plan the task. AI agents write the code. You decide what goes into the project.

Skribly joins these steps into one way of working. We build it in our spare time, as a non-commercial learning project.

From task to commit

Six steps. Four are yours and two belong to the agents.

  1. You plan

    A task starts in Skribly Tracker or arrives from Jira, Redmine, GitHub, GitLab or Linear.

    Skribly Tracker

  2. You start

    One click creates the branch, saves the task to a file and starts an agent with a ready prompt.

    Skribly Agent

  3. Agents work

    Claude Code, Codex, Cursor Agent and others run side by side, each in its own Git worktree.

    Skribly Agent

  4. They follow the rules

    Tests, reviews, audits and commit style come from one library. You do not teach each agent again.

    agent-skills

  5. You review

    You read the code changes and the security, accessibility and SEO audit results.

    Skribly Agent

  6. You close

    You accept the commit and add the comment and logged time to the task without leaving the app.

    Skribly Tracker

One task, step by step

Why we build this

The task was in the tracker, the work in a terminal.

We kept copying tickets into every agent. Now an agent starts from a file with the task and its comments.

With several agents, we lost track.

We could not see who was working and who was waiting for an answer. Skribly Agent shows this on one screen.

We told every agent the same things.

How to test, how to review, how to write commits. Those rules now live in one library that works in seven agents.

One session, from task to commit

This is what happens when you press Start with an agent. The labels on the left are the states the app shows on each pane.

AGENT-12 · Claude Codefeature/AGENT-12-show-time-log

  1. starting

    You start the task

    Choose a project and an agent. Keep the branch option on, or run the task in a separate worktree.

    Start with an agent

  2. starting

    The task becomes files

    The app saves the task and its comments, then creates a branch from your project's pattern.

    .skribly/tasks/AGENT-12/TASK.md

  3. working

    The agent reads and plans

    It reads the task and the state file, then proposes a short plan. A large task gets a written spec first.

    STATE.md

  4. waiting for a decision

    It asks for your OK

    Nothing changes until you answer. If the window is in the background, you get a system notification.

    "ok"

  5. working

    It works in stages

    After each stage it updates the state file, so another agent or a new session can pick up from there.

    Next step: …

  6. done

    It finishes its turn

    The pane is marked as done until you have seen the result, and the sidebar counts what is waiting for you.

    skribly agent wait --until done

  7. ready

    You read the changes

    Open the side-by-side diff, and run the audits if the change touches something visible.

    ⌘4

  8. ready

    You commit

    Suggest writes the message in your repository's style without a model, and no AI trailer gets through.

    feat(cart): save cart on logout

Rules you call by name

A skill is a short procedure an agent loads when it needs it. Here are six of the 39.

  • /task 482

    Task workflow

    Runs a task from a tracker issue or a sentence to an approved local commit.

  • /commit

    Commit in project style

    Proposes a message in the project's convention and commits only after you approve.

  • /review

    Self-review before commit

    Reviews the diff before committing, with severity, file:line and a fix for each finding.

  • /test-loop

    Focused test loop

    Runs only the checks affected by the change and fixes failures in up to three attempts.

  • /handoff resume 482

    Handoff and resume

    Saves or reads a state file, so another agent or a new session can continue.

  • /wcag-audit

    WCAG 2.2 AA audit

    Reviews changed UI with axe-core and a targeted checklist, and gives concrete fixes.

Three apps, one way of working

  • Where agents work

    Skribly Agent

    A desktop app for running several AI coding agents at once and keeping an eye on all of them.

  • Where tasks begin

    Skribly Tracker

    An issue tracker in the browser, with an API that lets agents read tasks the same way people do.

  • Where the rules live

    agent-skills

    39 portable skills with one installer for seven agents. It also works without the rest of Skribly.

Who it is for

  • Developers running several agents

    You want to see at a glance which agent is working and which one is waiting for you.

  • Small teams

    You want a simple tracker that people and agents can read in the same way.

  • Anyone repeating themselves

    You keep telling agents how to test and commit, and you would rather write it down once.

Short answers

Is Skribly a commercial product?

No. It is a non-commercial learning project that we build in our spare time.

Can I use it yet?

Not yet. The repositories are private and we will open them step by step. We share progress on LinkedIn.

Which agents work with it?

Skribly Agent runs 13 agents, including Claude Code, Codex, Cursor Agent and Gemini CLI, plus your own commands. agent-skills installs for seven agents.

Who decides what goes into the code?

You do. Skribly Agent prepares a commit proposal, and you check and approve it.
